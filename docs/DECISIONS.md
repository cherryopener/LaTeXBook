### 1-1. 시험 중에 고친 문제 (본 개발에 그대로 반영)

1. **SVG 그림 속 한글이 엉뚱한 글꼴로 찍힘.** 그림을 `<img>`로 넣으면 웹 글꼴을 쓰지 못합니다. → SVG를 본문에 직접 넣고, 글꼴을 CSS로 지정합니다.
2. **분수가 든 인라인 수식이 아랫줄과 겹침.** → 분수가 든 수식에 위아래 여유를 줍니다.
3. **장 첫 쪽에 머리말이 찍힘.** `@page chapter:first`와 `:nth(1)`는 Vivliostyle에서 첫 장에만 적용됐습니다. → 장 머리에서 "현재 절" 문자열을 빈 값으로 먼저 정해 두는 방식으로 해결했습니다.
4. **빈 쪽에 머리말·쪽 번호가 찍힘.** → `@page :blank`로 숨깁니다.
5. **퀴즈를 빼면 제목만 남음.** → 내용 없는 제목을 자동으로 지웁니다.
6. **좁은 2단에서 양쪽 정렬 때문에 띄어쓰기가 크게 벌어짐.** → 2단에서는 음절 단위 줄바꿈을 허용합니다. 1단은 단어 단위 줄바꿈입니다. (디자인 취향 문제라 6단계 테마에서 다시 정할 수 있음)

## 2. 라이브러리 불러오는 방식

- 기존 사이트 원칙은 "빌드 없이 CDN, 버전 고정"입니다.
- 그런데 원고 변환 라이브러리(unified 계열)는 작은 파일 수십 개로 나뉘어 있어서, CDN에서 하나씩 부르면 느리고 CDN의 자동 묶음 기능에 기댑니다. 이 작업 환경에서는 CDN 접속이 막혀 있어 그 경로를 시험할 수도 없습니다.
- **결정**: 변환기와 Vivliostyle을 각각 **미리 묶은 파일 1개**(`vendor/`)로 만들어 저장소에 넣습니다. 묶는 명령은 스크립트 하나로 남겨 언제든 다시 만들 수 있게 합니다.
  - 배포할 때는 빌드 단계가 없습니다. GitHub Pages가 파일을 그대로 올립니다.
  - 글꼴과 KaTeX CSS는 CDN(버전 고정)에서 불러옵니다.

## 3. 인쇄용 CMYK (윤전 4도)

- Vivliostyle CLI 11.4에는 `--cmyk` 기능이 있습니다. CSS에서 `device-cmyk()`로 지정한 색과, 미리 등록한 색 대응표(`reserveMap`, SVG 그림용)를 PDF 안에서 CMYK 값으로 바꿉니다.
- 이 기능으로 **본문 검정을 K 100%로 직접 지정**할 수 있습니다. 대응표에 없는 색이 나오면 빌드를 실패시키는 설정(`ifUnmappedColorsFound: "error"`)도 있습니다.
- 계획 4-2절에서 "모릅니다"라고 적었던 검은 글자 문제의 해결 경로입니다. 실제 PDF의 색 값 확인은 7단계에서 합니다.
- 그래서 그림 색 변환(8단계)은 "화면색 → 인쇄용 RGB"에서 끝내지 않습니다. **"화면색 → 정해진 인쇄 팔레트(CMYK 값이 정해진 색 목록)"**으로 바꿉니다. 팔레트는 C 역할이 2단계에서 만듭니다.

## 4. 라이선스

- 이 저장소의 라이선스는 사용자가 정한 **Apache-2.0**입니다(`LICENSE`, 2026-11-07 추가).
- **Vivliostyle.js는 AGPL-3.0입니다.** 둘은 함께 쓸 수 있습니다. Apache-2.0 코드는 AGPL 프로그램 안에 들어갈 수 있습니다. 다만 Vivliostyle을 묶어 배포하는 편집기 **전체**는 AGPL 조건(소스 공개, 같은 조건으로 배포)을 따르게 됩니다.
  - 우리가 쓴 파일은 Apache-2.0으로 둡니다.
  - 묶은 Vivliostyle 파일(`vendor/`)에는 AGPL 고지문과 원본 주소를 붙입니다.
  - 저장소가 공개라 소스 공개 조건은 이미 충족합니다. 실제로 달라지는 점은 "남이 이 편집기를 고쳐 배포하면 그것도 공개해야 한다" 정도입니다.
- 원고(`textbooks`)는 편집기가 읽는 데이터일 뿐이라 AGPL의 공개 대상이 아닙니다.
- 글꼴: Noto Serif KR, Pretendard 모두 OFL 1.1이라 PDF 포함과 배포가 가능합니다.
- 위 해석은 일반적인 이해이며 법률 검토를 거친 것은 아닙니다.

## 8. 정답(:::source)과 해설(:::solution)을 나눔 (2026-11-13 사용자 결정)

- 문항 아래 교사용 상자는 `:::source`(간단한 정답과 풀이 정보)만. 교사가 한눈에 보고 바로 풀 수 있게 하려는 것. 점선 아래 강조 색 글씨, 표시 글자 없음. 학생용에서는 빠짐(그 자리는 풀이 공간).
- `:::solution`(해설)은 원고에서는 지금처럼 문항 안에 쓰지만, 문제 쪽에는 두 판 모두 찍지 않고 책 맨 뒤 "A 정답과 해설" 장에 모은다. 예전의 "해설" 상자·표시는 없앰.
- "A 정답과 해설": **두 판 모두**(쪽 번호를 같게), 2단, 작은 글씨, 부 순서대로 부 제목 + `001 해설 글`. 해설 글은 원고 그대로 옮김(정답 표기는 저자가 해설 첫머리에 씀).
- 경고 이름을 바꿈: `solution-overflow` → `source-overflow`, `solution-spill` → `source-spill`.

## 9. 상자 안 글자 크기 (2026-11-13 사용자 결정)

- 팁(`:::tip`, "기억하기" 포함)·참고·더 생각해 보기·주의 상자 안 글은 본문 글자 크기(`print.fontSizes.body`)와 상관없이 **9pt 고정**. 상자 제목은 원래 9pt.
- 한 문장 정의(`:::def`)와 예제(`:::example`)는 본문 크기를 따른다.

## 10. Part가 많은 책의 첫 쪽 목차 (2026-11-14)

- 문제: 큰 표지(Part)마다 목차 한 단을 주는 방식은 4단까지만 있어, Part가 5개 이상인 책(시험 문항 책, 8 Part)은 첫 쪽 목차에서 3번째 Part부터 쪽 밖으로 잘렸다.
- 결정: Part가 5개 이상이면 두 단에 Part를 차례로 담는다. 단 나눔은 편집기가 줄 높이를 대략 세어 두 단이 가장 비슷해지는 큰 표지 줄 하나에만 둔다(CSS 다단 균형에 맡기면 Part 묶음이 단 사이에서 갈라질 수 있음). Part 4개 이하는 예전 그대로.
- 한 쪽에 정말 담을 수 없는 목차(예: Part 5개 × 장 4개, 절까지)는 막을 방법이 없으므로 `toc-overflow` 경고로 알린다. 목차가 길면 위 제목 그림 띠가 낮아지는데(영재역학은 조금 낮아짐, 보기에 괜찮음), 띠 아래쪽의 제목 글이 띠 밖으로 잘리기 시작할 때만 경고한다.

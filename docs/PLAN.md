### 1-1. GitHub 저장 방식 (질문 4에 대한 답)

**pull은 필요 없습니다.** 편집기가 브라우저 안에서 GitHub에 직접 읽고 씁니다.

- 어느 컴퓨터에서든 편집기 주소를 열고 → 원고 저장소에서 파일을 불러오고 → 쓰고 → "저장"을 누르면 그대로 커밋됩니다. 미리보기도 브라우저 안에서 그립니다. 내 컴퓨터에 원고 사본을 받을(clone·pull) 필요가 없습니다.
- pull이 필요한 경우는 VS Code 같은 다른 프로그램으로 원고를 고치고 싶을 때뿐입니다.
- **필요한 것: GitHub 토큰(접속용 비밀 열쇠)**
  - 원고 저장소 **하나에만**, **읽기·쓰기 권한만** 주는 토큰("fine-grained token")을 만듭니다. 만드는 방법은 단계별 설명서로 드립니다. 토큰 값은 대화창에 붙여 넣지 않습니다.
  - 컴퓨터마다 처음 한 번 편집기에 입력하면 그 브라우저에만 저장됩니다. 편집기는 이 값을 GitHub 말고 어디에도 보내지 않습니다.
  - 공용 컴퓨터에서는 "이 컴퓨터에 기억하지 않기"를 고르고, 컴퓨터를 잃어버리면 GitHub에서 토큰을 지웁니다.
- 원고는 브라우저 안에 몇 초마다 임시 저장되고, GitHub 커밋은 "저장"을 누를 때만 합니다. 글자마다 커밋하면 기록이 수천 개로 불어나기 때문입니다.
- 두 컴퓨터에서 같은 파일을 고쳤으면, 저장할 때 충돌을 알리고 두 판을 나란히 보여 줍니다. 어느 판을 남길지는 사용자가 고릅니다.
- **저장소는 둘로 나눕니다.**
  - `LaTeXBook`(지금 이 저장소): 편집기 프로그램 코드만 둡니다.
  - 원고 저장소(가칭 `cherryopener/textbooks`, **비공개**): 책 원고와 그림을 둡니다. 무료 플랜에서도 비공개 저장소를 만들 수 있습니다.

## 4. 인쇄·제본 기본값

### 4-1. 판형과 페이지

- 용지: A4(210×297mm), 인쇄소 제출용은 **A4 + 도련 3mm = 216×303mm**. 재단선 표시는 옵션입니다(인쇄소마다 요구가 다름).
- 좌우 페이지: 안쪽(제본 쪽) 여백을 바깥보다 넓게 하고, 좌우 페이지 여백을 거울처럼 뒤집습니다. 기본은 무선 제본 기준입니다.
- 쪽 번호: 꼬리말 바깥쪽. 가운데 정렬은 옵션입니다.
- 머리말: 장 제목 자동. 장 첫 페이지에서는 숨김. 로고·그림 장식은 예시 PDF를 받은 뒤 테마로 만듭니다(6단계).
- 장 시작: 오른쪽 페이지에서 시작하는 옵션(필요하면 빈 페이지 자동 삽입).
- 한글 줄바꿈: 단어 중간에서 줄을 바꾸지 않습니다(`word-break: keep-all`).
- 2단: 문서 전체 또는 특정 구간만. 제목·큰 그림은 두 단을 가로지를 수 있습니다.

### 4-2. 윤전 인쇄 때문에 추가하는 것

윤전은 옵셋 인쇄의 한 방식이라, 화면용 PDF를 그대로 내면 문제가 생길 수 있습니다.

- **CMYK PDF(PDF/X-1a)가 필요합니다.** 브라우저는 RGB PDF만 만듭니다. 그래서 7단계(Vivliostyle CLI `press-ready`를 GitHub Actions에서 실행)가 필수입니다.
- **검은 글자는 먹 한 색(K 100%)으로만 찍혀야 합니다.** RGB 검정을 그냥 CMYK로 바꾸면 네 가지 잉크를 겹친 검정이 됩니다. 그러면 작은 글자와 가는 수식 선이 번지거나 테두리가 어긋나 보입니다. `press-ready`가 이것을 어떻게 처리하는지는 **모릅니다.** 7단계에서 출력한 PDF의 색 값을 직접 확인합니다.
- **4도(컬러) 인쇄로 확정했습니다.** 색은 자유롭게 쓰되, 화면용 밝은 파스텔은 종이에서 흐리게 나오므로 인쇄용 진한 색으로 바꿉니다.
- **전체 쪽수 맞추기**: 윤전은 큰 종이에 여러 쪽을 한꺼번에 찍고 접습니다. 그래서 전체 쪽수를 인쇄소가 정한 배수로 맞춰야 할 수 있습니다(흔히 8 또는 16의 배수라고 알고 있으나, **추정이므로 인쇄소에 확인**합니다). 편집기에 "전체 쪽수와 맞추려면 더 필요한 빈 쪽 수" 표시를 넣습니다.
- **사진·그림 해상도**: PNG·JPG는 인쇄 크기에서 300dpi 이상인지 검사해 경고합니다. SVG는 해당 없습니다.

## 5. 원고 형식 (Physiklar 문법을 바탕으로)

### 5-1. 책 폴더 구조

Physiklar와 같은 구조를 씁니다. 그래서 Physiklar의 책 폴더를 거의 그대로 가져올 수 있습니다.

```
books/<책 id>/
  book.json               제목, 부제 + (편집기 전용) 판형·단 수·테마
  1-<부 이름>/part.json    부 제목
  1-<부 이름>/01-<장>.md   장 원고(첫머리에 title, summary)
  images/                 그림 (Physiklar의 public/books/<책 id>/ 에 해당)
```

### 5-2. 문법

| 문법 | 출처 | 화면(Physiklar) | 인쇄(편집기) |
|---|---|---|---|
| `$…$`, `$$…$$` | 공통 | KaTeX | KaTeX |
| `:::note` `:::tip` `:::warn` `:::think` | Physiklar | 상자 | 상자(인쇄용 색) |
| `::fig[설명]{src=… w=95}` | Physiklar | 그림 | 그림 + 자동 번호 "그림 1.3" |
| `:::quiz{answer=1}` | Physiklar | 정답을 맞혀야 넘어가는 퀴즈 | 인쇄하지 않음(원고에는 남김) |
| `::exp{id=…}`, `::anim{id=…}` | Physiklar | 웹 실험·움직이는 그림 | 인쇄하지 않음(원고에는 남김) |
| `:hl[…]`, `:red[…]` 등 | Physiklar | 형광펜, 글자색 | 도수에 맞춘 강조(1도면 밑줄·굵게) |
| `+++` | Physiklar | 화면 쪽 나눔 | 인쇄에서는 무시(원고에는 남겨 둠) |
| `:::columns` | 편집기 추가 | 무시 | 이 구간만 2단 |
| `::pagebreak` | 편집기 추가 | 무시 | 쪽 나눔 |
| `:::eq{#이름}` + `:ref[이름]` | 편집기 추가 | 번호 없이 식만 | 식 번호 (1.3) + 본문 참조 |
| ` ```plot ` | 편집기 추가 | 그림으로 내보내 사용 | 함수 그래프 |

- 편집기에 추가하는 문법은 Physiklar가 모르는 것들입니다. **"Physiklar로 내보내기"** 할 때는 이것들을 자동으로 벗겨 내거나 바꿉니다(식 번호는 `\tag`로, 그래프는 SVG 파일로).
- 원고를 짧게 줄이는 일(간소화)은 사용자의 편집 작업입니다. 편집기는 문법 변환만 합니다.

### 5-3. 함수 그래프 문법 (초안)

```plot
x: -1 .. 4
y: -1 .. 9
f: y = 2x + 1            "y=2x+1"
fill: f, 0 .. 3          넓이 칠하기 (x=0~3, 곡선 아래)
slope: f, 1 .. 2         기울기 삼각형 (Δx, Δy 표시)
point: (0, 1)            "y절편"
```

- 그래프마다 **SVG·PNG 내려받기 버튼**을 둡니다. 다른 프로그램에서 덧그릴 때는 SVG가 낫습니다. 선과 글자를 따로 고칠 수 있기 때문입니다.

### 8단계. Physiklar 브릿지 2권 → 한 권 이식 (첫 실전 예시)

**규칙: 본문 문장은 한 글자도 고치지 않습니다.** 말투와 내용 보강은 사용자가 합니다. 이식이 끝나면 원본과 결과의 글자만 뽑아 비교해서, 문장이 바뀌지 않았음을 기계적으로 확인합니다.

옮길 분량(2026-11-07 기준)

| | 역학 | 전자기 | 합계 |
|---|---|---|---|
| 장(원고 파일) | 12 | 12 | 24 |
| 그림(SVG) | 22 | 23 | 45 |
| 퀴즈 | | | 148 |
| 웹 실험·움직이는 그림 | | | 22 (`::exp` 17, `::anim` 5) |

- 책 구성(기본안): 『브릿지 물리』 한 권, **1부 역학 / 2부 전자기**. 각 부 아래에 지금의 단원(운동의 기술 등 4개씩)을 장으로, 원고 파일 24개를 절로 둡니다.

| 작업 | 내용 | 단계 |
|---|---|---|
| 8-1. 원고 이식 스크립트 | 폴더 구조 합치기, 그림 경로 바꾸기. 퀴즈·웹 실험은 원고에 그대로 두고 인쇄에서만 숨김. "아래 실험에서"처럼 빠진 실험·퀴즈를 가리키는 문장 목록을 만들어 사용자에게 드림(문장은 고치지 않음) | 2 · sonnet/high |

| 8-3. 그림 검토 | 변환 전후 그림을 나란히 놓고 읽기 어려운 색·겹침·사라진 요소를 찾음 | 3 · opus/medium |

## 7. 서브에이전트에게 넘길 내용 (공통)

- 목표, 맡은 역할, 맡은 폴더(이 폴더만 수정 가능)
- `docs/FORMAT.md`, `docs/INTERFACES.md`, `docs/DECISIONS.md` 경로
- 견본 원고와 합격 기준
- CDN 주소에 정확한 버전을 적는 규칙
- 화면에 보이는 글자는 한국어
- 보고 형식: ① 만든 것 ② 약속과 다르게 한 곳 ③ 확인한 것과 못 한 것 ④ 다른 폴더에 대한 변경 제안
- `Agent` 호출 때 `model`과 `effort`를 6절 표대로 반드시 지정합니다.
- 토큰 같은 비밀 값은 어떤 서브에이전트에게도 넘기지 않습니다. 저장 기능 시험은 시험용 저장소와 사용자가 직접 입력한 토큰으로 합니다.

## 8. 위험과 대책

| 위험 | 영향 | 대책 |
|---|---|---|
| 특정 구간만 2단이 페이지를 넘어갈 때 엔진이 제대로 못 나눔 | 2단 기능 일부 제한 | 0단계에서 먼저 확인. 안 되면 "2단은 장 단위로만" 같은 제약을 정함 |
| 원고가 길어지면 실시간 미리보기가 느려짐 | 입력이 버벅임 | 미리보기는 지금 쓰는 장만. 전체 페이지는 PDF 뽑을 때만 계산 |
| CMYK 변환 시 검은 글자가 네 가지 잉크로 찍힘 | 작은 글자·수식이 번져 보임 | 7단계에서 PDF 색 값을 직접 검사. 안 되면 변환 설정을 따로 만듦 |
| 토큰 유출 | 원고 저장소를 남이 고칠 수 있음 | 저장소 하나·읽기쓰기만 주는 토큰, 만료일 설정, 유출 시 GitHub에서 즉시 삭제 |
| 상용 한글 글꼴을 쓰고 싶을 때 | 공개 저장소에 글꼴 파일을 올릴 수 없음 | 기본은 OFL 글꼴. 상용 글꼴은 비공개 원고 저장소나 사용자 컴퓨터에서만 불러옴(라이선스가 허용하는 경우만) |
| 퀴즈·웹 실험을 빼면 그것을 가리키는 문장이 남음 | 종이책에서 어색한 문장 | 8-1에서 해당 문장 목록을 드림. 고치는 것은 사용자 |
| Physiklar 문법이 앞으로 바뀜 | 두 방향 변환이 어긋남 | Physiklar `docs/WRITING_GUIDE.md`를 기준 문서로 삼고, 바뀌면 `FORMAT.md`도 같이 고침 |
